# Лабораторная работа «Ничего не падает»

## Настройка и инструкция по запуску проекта

Для проекта настроен JDK 25: он указан в JAVA_HOME и выбран для Gradle в IntelliJ IDEA. Kotlin и Gradle отдельно устанавливать не нужно, используется Gradle Wrapper. Код находится в app/src/main/kotlin/schedule, тесты - в app/src/test/kotlin/schedule.

Все команды выполняются из корня проекта.

Сборка с тестами на macOS/Linux:

```bash
bash ./gradlew build
```

Подготовка скрипта запуска:

```bash
bash ./gradlew build :app:installDist
```

Выбор занятий по датам:

```bash
./app/build/install/schedule/bin/schedule period --file samples/clean.txt --from 2026-09-28 --to 2027-05-13
```

Выбор по типу:

```bash
./app/build/install/schedule/bin/schedule type --file samples/dirty.txt --type EXAM
```

Вывод ошибок:

```bash
./app/build/install/schedule/bin/schedule errors --file samples/dirty.txt
```

Сравнение с эталонами:

```bash
python3 tools/verify.py
```

На Windows вместо `bash ./gradlew` используется `.\gradlew.bat`, вместо пути к приложению - `.\app\build\install\schedule\bin\schedule.bat`, вместо `python3` - `python`. Аргументы команд остаются теми же.

## Этап 1

Созданы интерфейс Session с датой и темой и четыре класса занятий. Lecture и Practice содержат место и хотя бы одного преподавателя, Exam - не менее двух разных преподавателей. У Cancelled есть только дата и тема.

Для занятий я выбрал обычные class с val и проверками в init. Ограничения проверяются даже при прямом вызове конструктора. Классы закрыты для наследования, copy и сеттеров нет. Равенство занятий по содержимому здесь не требуется. Для AuditEvent выбран data class: это простая запись с неизменяемыми полями операции и количества.

Список преподавателей копируется и оборачивается в Collections.unmodifiableList. Одного val недостаточно: оно запрещает заменить ссылку, но не изменить содержимое списка. Пробелы не обрезаются, регистр не меняется, повторы автоматически не удаляются.

InMemorySessionRepository сохраняет порядок добавления и одинаковые занятия. Метод all возвращает независимый защищённый снимок: через него нельзя изменить реестр, а новые добавления не меняют старый результат.

В AuditedSessionRepository использовано SessionRepository by delegate. Переопределены add и addAll, потому что внутренний addAll делегата не вызывает add обёртки. После успешного вызова записывается одно событие и увеличивается addedCount. Пустой addAll создаёт событие с количеством 0, all не создаёт событий. Журнал доступен через защищённый снимок auditLog и автоматически не выводится.

Я проверил попытки сломать модель:

- Пустая и пробельная тема отклоняется проверкой в init с IllegalArgumentException.
- Годы 0 и 10000 отклоняются. Границы 1 и 9999 допустимы.
- Действующее занятие без преподавателей и сдача с одним преподавателем отклоняются проверкой количества.
- Два одинаковых имени запрещены проверкой повторов. Ivanov и ivanov допустимы как разные имена.
- Изменение и очистка исходного списка не меняют занятие благодаря копированию.
- Изменение выданного списка через MutableList вызывает UnsupportedOperationException.
- Обхода через copy и сеттеры нет: эти методы отсутствуют.

Дополнительно проверены неверные места и имена, внешние пробелы, управляющие символы, снимки реестра, порядок и повторы, пустой пакет и ошибки делегата.

## Этап 2

Session сделан sealed-интерфейсом. Все четыре типа учтены в when без else. Для разбора добавлена sealed-иерархия ParseResult: Success с занятием или Rejected с номером строки и структурированной причиной. Форматирование сообщений вынесено в отдельную функцию.

В парсере соблюдается приоритет: разделитель, число полей, пустые поля, дата, тип, число преподавателей сдачи, остальные ограничения. В последней группе сначала проверяются управляющие символы, затем внешние пробелы, поля отмены, место, неверные имена и повторы.

Для дополнительных причин выбраны сообщения после «line N:»:

- control character in field "FIELD" - управляющий символ.
- surrounding whitespace in field "FIELD" - внешние пробелы в поле или имени.
- type "CANCELLED" requires '-' in field "FIELD" - неверное поле отмены.
- active session requires a location other than '-' - отсутствует место.
- invalid teacher name "VALUE" - пустое имя или «-».
- duplicate teacher name "VALUE" - повтор имени.

Вместо FIELD подставляется имя поля, вместо VALUE - исходное значение. Кавычки и обратные косые черты экранируются, управляющие и не-ASCII символы записываются как \uXXXX для каждой UTF-16 единицы.

Команды читают файл построчно, сохраняют порядок и проверяют даже строки вне фильтра. `period` включает обе границы дат, `type` выводит преподавателей, `errors` - отказы и их количество. Код 0 означает отсутствие отказов, 1 - наличие отказов, 2 - ошибку аргументов или чтения. Итог печатается только после полного чтения.

Я добавил тесты на несколько дефектов одновременно, экранирование, високосные даты, конечные пустые поля, границы периода, пустой файл и ошибки вне фильтра. Проверена ошибка чтения после частичного вывода: прежние строки сохраняются, а итог Total не появляется. Вывод и коды завершения совпали с эталонами при проверке `tools/verify.py`.

## Задание со звёздочкой

Добавлена функция session.reschedule(newDate). При успехе возвращается RescheduleResult.Success с новым занятием того же типа и прежними темой, местом и преподавателями. Исходный объект не меняется, даже при переносе на ту же дату создаётся новый.

Год вне 1..9999 даёт InvalidDate, отменённое занятие - CancelledSession независимо от новой даты. В тестах проверены все действующие типы, сохранение данных, неизменность исходного объекта, границы лет, високосная дата и защита списка после переноса. Для этой операции достаточно функции, новая команда CLI не добавлена.
